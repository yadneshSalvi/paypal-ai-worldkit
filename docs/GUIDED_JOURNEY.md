# Guided creator journey

Open the saved creator workbench and choose **Guide me**. The six steps connect listening, a component change, a repair, complete-system comparison, a deliberate commerce handoff and retained evidence. Opening, changing steps and returning after reload do not create a workspace, save an edit, start audio or call a provider.

The starting Sample uses two dynamic microphones. Previewing an AT2020 in source position 2 exposes its missing phantom power and a silent modeled second track. The saved edition stays unchanged until the exact preview is approved. Applying the recorder's phantom-power repair restores the modeled signal, while the exact hub power supply remains an evidence question. The journey never changes that unknown to a passed physical test.

The guide uses the current saved equipment and settings. It does not reset a customized system, substitute a confirmed equipment-passport identity, or present an already-applied change as a new experiment. The comparison cards use the evaluated alternatives already returned for that workspace. Cart lab, Studio and Living kit retain their separate approval and provenance rules; following a link creates no order or spending authority.

## Preview and save contract

`POST /api/workbench` accepts a strict `preview` or `apply` command from the current same-origin private workspace. Both pin the original revision and graph hash. Preview uses the current sources, catalog observations, rules and engineering-review authority. Its fingerprint binds the exact edit, current authority, checks and routing; only the wall-clock display label is excluded.

Applying requires the preview fingerprint, an explicit model-change acknowledgement and a UUID. The saved revision, current head, edit event and append-only command receipt commit together. Repeating the original UUID and body returns its original saved edition plus the actual current head. It never rewinds a later edition. A different body, stale graph or changed evidence requires a new preview. Current stored authority is checked after lock waits and before commit; the original deadline is never extended.

The browser retains an exact scoped request before sending it. An unresolved response blocks another guided save. Recovery sends only that original request, and an acknowledged save with a failed subsequent read recovers through a read alone. Mount, reload and reopening the guide never dispatch a retained mutation automatically. A different actor, kit or original expiry cannot display or replay another scope's journal. Malformed acknowledgements, unavailable storage and expired authority remain explicit holds.

## Audio and evidence boundaries

Soundcheck generates original tones from the saved graph. Audio begins only after Play and only reports a start after the browser audio context enters its running state. Closing, changing the graph or failing audio setup closes allocated resources; a late permission answer cannot credit another revision. This demonstrates software routing, not equipment performance or a listener's assessment.

The final step links the exact graph to assembly, primary sources, the test notebook and the research notebook. Physical observations, qualified reviews and consented participant outcomes must still be provided through those workflows. Sample actors, generated audio, modeled checks and actual provider receipts remain distinct.

## Validation and migration

The affected controls exercise installed React, the shared modal and Soundcheck, plus real loopback HTTP and PostgreSQL for authority, locks, byte limits, concurrent UUIDs, rollback and lost-response recovery. Existing compiler, routing and ownership controls remain applicable. Native playback, mobile paint and the whole-page handoff require the separately recorded browser qualification.

The additive schema is `WORKBENCH_SQL` in `src/server/workbench-db.ts`: one command table, one guard function and one immutability trigger. Use the existing migration command for a fresh installation. Apply production schema changes only through the documented release backup and exact additive migration procedure. No new dependency or environment variable is required for the deployed product.
