# Scoped PayPal observations

Studio can preserve a new observation of an already captured WorldKit sandbox order, including a controlled kit amendment alongside its original receipt. An owner selects **Read order** or **Read reporting page**. The official PayPal Agent Toolkit performs the read; the result retains the exact order, kit revision, graph hash, capture, timestamp, digest and bounded coverage. This does not reconcile or rewrite payment state. Reporting absence does not establish a missing capture or refund.

The optional `payment:read` MCP grant exposes `read_payment_evidence`. Existing kit grants do not include or advertise that tool. Its strict input accepts an application order ID, the original graph hash, operation and UUID request identity. Provider IDs, amounts, URLs and arbitrary Toolkit parameters are resolved server-side. Grant scope, current allowed kits, expiry, workspace ownership, accepted quote and recorded order/capture bindings are rechecked before OAuth, before the resource GET and before disclosure. Repeating one exact request identity returns its saved attempt without another provider request. Changed inputs or caller identities are rejected. Lost or failed reads remain visible; a fresh observation requires a new deliberate request.

`WORLDKIT_TOOLKIT_READS_ENABLED=1` enables reads only with the isolated sandbox configuration and active providers. Provider-disabled QA workspaces retain saved observations but cannot call PayPal. The HTTP endpoint is `/api/payment-evidence`; the browser automatically loads saved history, never a provider read. The latest twenty attempts are shown. Each workspace permits at most six new reads per minute; MCP has an additional four-read-per-minute scope limit.

The transport pins `@paypal/agent-toolkit@1.11.0` and Axios `1.21.1`. Only the public OpenAI Toolkit entry is loaded. Its public Axios middleware is isolated with `AsyncLocalStorage` and admits one OAuth POST followed by one exact sandbox GET, with no redirects or retries, a 20-second deadline and a 1 MiB response bound. Independent wire validation prevents swallowed reporting errors from becoming an apparent empty result. Safe observation fields exclude payer information, wallet tokens, credentials and raw provider payloads. The existing APIMatic payment core `0.2.4` remains unchanged and owns financial actions.

The scoped `mathjs@15.2.0` override removes its reported advisory. The installed Toolkit tree retains ten high and one moderate audit findings in inherited dependencies, including Zod 3 and unused adapters; this is not an audit-clean dependency tree. Toolkit Zod constructs static tool schemas; WorldKit validates external inputs through its root Zod 4 schemas and constructs the two native argument objects itself. No user-defined schema or arbitrary Toolkit action is exposed. The Vercel AI and LangChain adapters are not imported by this integration. These bounds limit the exposed surface; they do not patch upstream packages or qualify other adapters. Do not force a major Zod override or downgrade Toolkit merely to change audit counts. [Official Toolkit source](https://github.com/paypal/agent-toolkit/blob/main/typescript/README.md).

Qualification covers 143 unit checks, 146 PostgreSQL checks, TypeScript and an optimized production build. Transport tests use explicitly synthetic responses. Separate actual-provider qualification read the exact owned $8 captured/refunded amendment through two OAuth requests and two bounded GETs, all returning 200. Twelve original tables stayed unchanged. Native checks cover saved observations, failure retention, reload, Escape, the unchecked optional grant and a 390-pixel viewport. The [local qualification record](evidence/payment-evidence-local-qualification.json) retains the earlier failed attempts and their scope.


### Historical controlled amendment binding
A controlled kit amendment retains its paid graph in its immutable amendment proposal, not necessarily in `wk_revisions`. Evidence ownership resolves the exact accepted amendment and gross claim, verifies proposal/merchant-quote digests and the tenant-owned commitment, and binds its retained after-graph. A separately consented restoration supplement resolves its exact compensation digest and restoration graph. Both paths recheck the retained manifest before OAuth, GET and disclosure. No record is copied into ordinary revision history.

The retained APIMatic capture projection may carry the exact application custom ID on the capture while omitting it on the order projection. Ownership requires at least one matching custom ID across the exact tenant-owned order/capture pair and rejects every conflicting value; it also requires the exact parent, amount and currency. The 21 evidence PostgreSQL checks include historical amendments, restoration supplements, foreign commitments, digest tampering and changes between OAuth and GET.
