# Complete systems and upgrade journeys

**Compare** evaluates complete creator systems for the current hard brief, explains the tradeoffs, and preserves each comparison as an immutable edition. A saved preference is separate from applying a graph revision. Neither operation grants purchase, funding, fulfillment, refund, return or repair authority.

This source milestone is locally qualified with fictional Sample equipment and provider-disabled PostgreSQL/HTTP checks. It does not claim hosted qualification, genuine human engineering review, physical performance or an exhaustive market search. The broader domain-pack, research, Store Sync, authentic-event, physical-study and release work remains active.

## Whole-system checks

The four existing creator architectures remain the starting point: host recording, independent recorder plus stream, mixer recording plus stream, and a recorder feeding the camera through an explicit level converter. Every generated configuration runs the existing graph verifier and the additional `worldkit.synthesis.2` checks before it can receive a feasible label.

The checks cover the typed hard target and budget, isolated inputs, current application and firmware modes, distinct outputs, monitoring count, source-backed port maps, exact cable ends and protocol, cable bandwidth/power ratings, the shared USB route, the complete declared power load, included battery premises, recording storage, owned positions, total passport quantities and committed equipment. Unknown source, cable, battery, offer or review premises remain unknown. A sourced false capability or incompatible known resource is a conflict.

The search evaluates up to six exact audio profiles and three microphone identities per architecture. It retains the existing camera, host, hub, capture, monitoring and power roles and selects the additional sourced cable/media identities deterministically. It models at most 32 voice positions; a larger original target remains unsatisfied. This bound never changes the saved goal. The interface discloses this scope, all evaluated candidates, rejected candidates and any bound reached. It does not claim every combination in the market was searched.

Every new unit, including cables, media and a level converter where required, has an estimate line. Confirmed owned equipment has zero additional procurement cost. Live catalog observations require a previously confirmed exact product/variant identity, matching profile hash, current snapshot and USD integer minor units. A newer stock-out supersedes an earlier available observation. Stale, unavailable, mismatched and other-currency observations cannot supply an actionable price. Unknown shipping or tax keeps the complete price unknown. Sample offers explicitly use fictional prices and zero shipping/tax; they are not retailer observations.

## Explainable objectives

Only complete feasible systems enter the Pareto comparison. One system dominates another when it is no worse on landed cost, new units, connection count, host recording dependencies, retained units and sourced spare inputs, and strictly better on at least one. Unknown objectives cannot dominate. Stable design keys break ties.

- **Budget** selects the lowest complete estimate among evaluated non-dominated configurations.
- **Balanced** first reduces host recording dependencies, then connections, then cost, using a different architecture when one exists.
- **Room to grow** prioritizes sourced spare independent inputs, then fewer host recording dependencies, then cost, using another distinct architecture when one exists.

The product does not fabricate three labels when only one or two distinct feasible architectures exist. The complete Sample fixture produces a $253 host route, a $309 recorder route and a $424 mixer route. Its separate camera-feed route is also checked but is dominated on the declared objectives. Lower-priced fictional microphones require unsupported 96 V power and remain visibly rejected, including when phantom power is enabled.

When no system satisfies the brief, the edition retains all original blockers. The relaxation search considers explicit budget increases and lower isolated-track counts, evaluates the whole proposed graph again, minimizes the number of changed user constraints, and removes larger changes beaten on every changed constraint. Minimality applies to the disclosed evaluated catalog, not the entire market. Sources, owned equipment, safety/resource premises and independent review are never waived. Reviewing a relaxation creates a separate proposed-goal edition; applying its chosen graph requires another explicit acknowledgement of the goal changes.

## Versioned decisions

`GET /api/synthesis` opens the latest comparison; `?edition=<id>` opens an exact prior edition. `POST /api/synthesis` accepts strict commands in `packages/synthesis/contracts.ts`:

| Command | Result |
| --- | --- |
| `compare` | Save an edition bound to the expected current revision and graph hash. |
| `prefer` | Save a versioned preference, preserving the current graph. |
| `relax` | Create a separate edition for an explicitly reviewed hard-goal proposal. |
| `rebase` | Re-evaluate against the current graph and evidence, retaining the old edition and matching the earlier intent where possible. |
| `journey` | Save independently checked first/later system stages with conditional reuse. |
| `apply` | Recheck the exact saved preference, then create a normal immutable kit revision. |

Each mutation requires the current workspace owner, an exact command identity, and the expected edition hash/choice version. Exact replay returns the durable prior result. Reusing a request identity with different content fails. Two racing commands cannot overwrite a newer choice or graph. A conflict retains the selected candidate and earlier edition and offers an explicit reload/rebase path. Applying a research plan requires acknowledgement of unresolved premises; a hard-conflict plan cannot be applied.

The application boundary checks current session access, original goal and revision, profile/variant/firmware identities, primary-source heads, engineering editions and authority, passport quantities, observed offers and equipment commitments. Existing rows remain locked through application; a second version-vector read detects immutable observations appended during evaluation. A time-expired offer or invalidated engineering edition also makes the comparison stale. An applied comparison stays readable as the exact historical decision and requires a new edition before another graph change.

PostgreSQL append-only triggers protect editions, commands, choice events, observations and journeys. The mutable choice head advances exactly one version and cannot be changed after application. Each previous preference and its exact candidate identity stays in the choice log. Original graph/certificate rows and payment history are read, never rewritten, by synthesis.

## Proposed upgrades

A journey contains two genuinely different proposed architectures. The later stage must add sourced input capacity or remove a host recording dependency. Each stage retains its own graph, complete certificate, source requirements, component/connection diff, full-system estimate and conditional incremental estimate. Reuse counts each prior proposed unit once, by exact profile identity and quantity.

Conditional reuse is not ownership. Before relying on it, the earlier proposed equipment must actually be acquired and confirmed in the passport. Later graph application requires a fresh comparison; purchases and repairs keep their separate authority processes. Replaced acquired equipment stays with its owner; no resale credit, refund, return or delivery is assumed.

## Experience and scoped resources

The comparison cards use original logical dioramas to distinguish where files live and where the stream travels. They do not claim physical jack coordinates. The reading room keeps hard requirements, component/wiring changes, every cost and exact sources/versions together. History opens exact old editions and their immutable choice log. Keyboard focus reaches the selected system; review dialogs trap focus, restore it on cancellation, and move errors into an actionable recovery view. Mobile layouts retain every path and evidence field. Reduced motion is respected.

The existing modeled soundcheck is offered only for supported two-track onboard graphs whose power, routing and source/resource checks pass and whose paths the actual renderer supports. Host recording and other unsupported configurations get an explanation instead of fabricated output. Generated original test signals remain a routing model, never a hardware recording or physical test.

The existing `kit:verify` grant can list and read:

```text
worldkit://systems/{revisionId}/{graphHash}/{editionId}/comparison
worldkit://systems/{revisionId}/{graphHash}/{editionId}/upgrades
```

These resources return exact private planning editions, current freshness and explicit authority limits. Current scope, kit membership, expiry and revocation are checked on every read. They add no mutating synthesis tool and no Store Sync contract. Local SDK/HTTP tests are not qualification of an actual external deployment or provider.

## Validation and release gates

The local checks cover distinct systems, Pareto ties/dominance, rejected cheap components, exact cables and resource limits, missing/false facts, owned/purchased preservation, stale prices/sources/goal/inventory/review authority, minimal relaxations, immutable history, owner/tenant denial, duplicate and racing commands, research-plan acknowledgement, SDK resources and actual local production HTTP transport. They assert unchanged nonempty fictional financial rows as well as zero new provider/model effects.

The independent handoff retains a QA launcher, fresh native fixtures, failed attempts, an exact source/dependency/build manifest, and a desktop/390/360/keyboard/concurrency protocol. The local native-entry overlay is excluded from product integration. Native acceptance, integration, hosted migration/deployment and actual-provider/model qualification remain separate release gates. No genuine human review or physical test is claimed by this unit.
